📧 Email Digest (Automated) Runs daily at 9am even when app is closed
Get a daily email summary of: overdue Girvi loans, pending balances, yesterday's revenue, and top action items.
Setup: Uses Supabase pg_cron + Resend.com (free tier: 100 emails/day).
Setup steps:
  1. Sign up free at resend.com → get your API key
  2. Add key to Supabase: Settings → Edge Functions → Secrets → RESEND_API_KEY
  3. Create Edge Function daily-digest (template in docs)
  4. Enable pg_cron: SELECT cron.schedule('daily-digest', '0 3 * * *', $$SELECT net.http_post(...)$$)
Email stored locally — used by the Edge Function when you set it up.

SQL Setup
JewelOS's browser code never talks to Supabase tables directly — it never has, and never should, be given permission to. All reads and writes go through two secure Edge Functions instead: Browser → store-proxy → Supabase for shop data and counters, and Browser → auth-gateway → Supabase for login/signup. Those functions hold the service-role key on the server only — it is never shipped to the browser. Run the migrations below once in the Supabase SQL Editor (or via supabase db push) and deploy the three Edge Functions (store-proxy, auth-gateway, razorpay-webhook); that's the entire setup. There is no anon/public policy to add for store, auth_store, or counters — access to all three is intentionally locked down to server-side code only. 
-- JewelOS — secure production setup
-- Run supabase/migrations/001_lockdown_rls.sql, then
-- supabase/migrations/002_atomic_transactions.sql, in the Supabase SQL
-- Editor (or `supabase db push` from the repo). Both files are idempotent
-- and safe to re-run.
--
-- What they do, in short:
--   * Create store / auth_store / counters / login_attempts /
--     payment_events / password_reset_tokens.
--   * Enable Row Level Security on every one of them.
--   * Grant NOTHING to anon or authenticated — this is intentional.
--     There is no "USING (true)" policy anywhere in this schema.
--     Only the service_role key (used exclusively inside the
--     store-proxy / auth-gateway / razorpay-webhook Edge Functions,
--     never sent to the browser) can read or write these tables.
--   * Add increment_shop_counter() and store_cas_write(), the atomic
--     Postgres functions store-proxy calls for invoice/order/Girvi
--     numbering and for conflict-safe multi-device saves.
--
-- Then deploy the Edge Functions:
--   supabase functions deploy store-proxy
--   supabase functions deploy auth-gateway
--   supabase functions deploy razorpay-webhook
--
-- The browser only ever calls those three function URLs — never a
-- Supabase table URL (/rest/v1/...) directly.
